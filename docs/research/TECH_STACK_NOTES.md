## A. pjproject 2.16 / 2.17

Releases: 2.16 = 2025-11-26, 2.17 = 2026-04-22 (https://github.com/pjsip/pjproject/releases).
2.16 focus: RTT (RFC 4103), parallel conference bridge, A/V sync, client-side dialog-event (BLF) package. 2.17 focus: async SIP auth, AI/speech media port, CMake improvements, deadlock fixes, and a long list of security fixes (ICE, H.264, Opus, DNS, multipart, GnuTLS chain verify) -> use 2.17, not <=2.15. Backward-incompat in 2.17: INVITE transaction termination delay / no 200 OK retransmit (#4765), Opus lib name on MSVC (#4888). Release notes: https://github.com/pjsip/pjproject/releases/tag/2.17

### A1. License

Must ship corresponding source for the whole combined work (Flutter UI + FFI glue + pjsip). H.264/G.729/AMR carry patent/royalty considerations [U].

### A2. Build procedures
General: pjproject builds **static libs** (.a / .lib). For Dart FFI you must link them into **your own shared library** (libsoftphone.so/.dylib/.dll or a framework) exposing a thin C API. pjproject does not ship ready-made DLLs on Windows ("PJSIP does not provide DLL projects for Windows" - https://docs.pjsip.org/en/latest/get-started/windows/build_instructions.html [V]).

**Android** (https://docs.pjsip.org/en/latest/get-started/android/build_instructions.html [V]; configure-android in repo [V])
- `config_site.h`: `#define PJ_CONFIG_ANDROID 1` + `#include <pj/config_site_sample.h>` (+ `PJMEDIA_HAS_VIDEO 1` if wanted).
- `export ANDROID_NDK_ROOT=...; TARGET_ABI=arm64-v8a APP_PLATFORM=android-23 ./configure-android --use-ndk-cflags --with-ssl=$OPENSSL_DIR --with-oboe=$OBOE_DIR; make dep && make clean && make`. One ABI per build (arm64-v8a default; also x86_64 for emulator; armeabi-v7a, x86 via TARGET_ABI). `make distclean` between ABIs; rebuild OpenSSL/Oboe/opus per ABI+API level.
- NDK: docs example uses r28 (28.0.12916984); script requires NDK >= r17 for the default flag path. Min platform forced to >= 23 by script. **16 KB page size** (Play requirement for targetSdk 35+): use NDK r27+ and PR #4068, or `-D__BIONIC_NO_PAGE_SIZE_MACRO` + `-Wl,-z,max-page-size=16384`. Native Android codecs need API 28+.
- Audio backends in source: Oboe (`oboe_dev.cpp`, `PJMEDIA_AUDIO_DEV_HAS_OBOE`, `--with-oboe`), OpenSL ES (`opensl_dev.c`, default 0), Android JNI (`android_jni_dev.c`, default = PJ_ANDROID, uses Java AudioRecord/AudioTrack). **Oboe is the native path and needs no Java/JNI** (but needs libc++_shared + liboboe built from google/oboe). JNI backend requires a JavaVM (pj_jni_... / `pj_jni_attach_thread`) - avoid; use Oboe. SWIG/Java only needed for pjsua2 Java [V per docs]. Caveat [U]: some pjsip Android features (camera video, JNI audio, OpenSSL on API<23) need JNI_OnLoad / Java classes; with Oboe+audio only you can skip Java.
- Package: put libssl/libcrypto/liboboe(+libc++_shared.so) and your own libsoftphone.so in `android/app/src/main/jniLibs/<abi>/`.

**iOS** (https://docs.pjsip.org/en/latest/get-started/ios/build_instructions.html [V])
- `config_site.h`: `PJ_CONFIG_IPHONE 1` + sample include. `./configure-iphone` (wraps ./aconfigure). Default ARCH arm64; MIN_IOS default per docs iOS 7 -> **set `MIN_IOS="-miphoneos-version-min=13.0"`** (script header says 11.0; docs say 7.0 - inconsistent, set explicitly).
- One build per arch/SDK. Simulator: set `DEVPATH` to iPhoneSimulator.platform/Developer, `ARCH="-arch arm64"` and `MIN_IOS="-mios-simulator-version-min=13.0"` (and x86_64 for Intel Macs; docs' simulator example uses `CFLAGS`/`LDFLAGS` with -arch). `make distclean` between.
- XCFramework: docs describe `libtool`/`lipo` to merge per-arch .a into one libPJSIP.a per platform (device / simulator / macOS), then `xcodebuild -create-xcframework -library ... -headers ...`. Device arm64 and simulator arm64 cannot share one lipo'd archive (same arch, different platform) - hence xcframework.
- TLS: either Apple Network framework backend (`PJ_SSL_SOCK_IMP_APPLE`, iOS13+; docs call it experimental on the iOS page but recommended on the SSL page) or OpenSSL (`--with-ssl=`; build OpenSSL 1.1.x/3.x for iOS yourself). DTLS-SRTP needs OpenSSL (see A3).
- Video: no codec on by default; VideoToolbox H.264 (`PJMEDIA_HAS_VID_TOOLBOX_CODEC`), openh264, libvpx.
- Define `PJ_AUTOCONF=1` in the consuming project.

**macOS**
- Docs (posix build page [V]) cover only autoconf; cross-arch via `CFLAGS="-arch x86_64" LDFLAGS=... ./configure --host=x86_64-apple-darwin`. No universal recipe in docs. Practical: build twice (arm64, x86_64) and `lipo -create` the .a files, or link your dylib per-arch and lipo the dylib [U - standard practice]. Use CoreAudio (`coreaudio_dev.m`), darwin_dev.m (AVFoundation capture), metal_dev.m/ios_opengl for render.
- CMake (new in repo): `CMakeLists.txt` (cmake >= 3.28) exists; README of build says **experimental, tested on Linux x86_64 and macOS only**; CI job `cmake-build` in ci-linux.yml. For Apple, CMake options `-DPJLIB_WITH_SSL=apple -DPJLIB_WITH_IOQUEUE=select` etc. (https://docs.pjsip.org/en/latest/specific-guides/security/ssl.html [V]). WebRTC AEC/AEC3 deps are excluded from CMake on Apple/MinGW.

**Windows**
- Official: `pjproject-vs14.sln` (VS2015-2022, default toolset v143). CI (https://github.com/pjsip/pjproject/blob/2.17/.github/workflows/ci-win.yml [V]) runs `msbuild pjproject-vs14.sln /p:PlatformToolset=v143 /p:Configuration=Release /p:Platform=win32 /p:UseEnv=true` (**CI only tests Win32**; the .sln does contain x64 configs [V, 590 'x64' hits] and docs link PR #2807 for ARM64 - ARM64 status unverified). OpenSSL on CI comes from `pjsip/third_party_libs` openssl-1.1.1s-win.zip (stale; build OpenSSL 3.x yourself).
- Configs: Debug/Release (MSVCRT static? "LIBC"), -Static, -Dynamic; pick one matching the CRT of your wrapper DLL and OpenSSL (/MD recommended for a Flutter DLL).
- config_site.h: enable `PJMEDIA_HAS_VIDEO`, `PJMEDIA_VIDEO_DEV_HAS_DSHOW`, etc. as wanted. Audio: WASAPI (`wasapi_dev.cpp`, default on for non-ancient VS) and WMME.
- Alternatives: MinGW-w64 via `./configure` (documented guide exists [V - linked]); CMake not supported on Windows/MSVC yet (experimental, Linux+macOS only; schannel is "accepted but not implemented" in CMake - use VS build for Schannel [V]). Recommended: msbuild on `windows-latest` GitHub runner producing static libs, then link into a wrapper DLL built with CMake/MSVC.
- Windows TLS: Schannel (`PJ_SSL_SOCK_IMP_SCHANNEL`) set in config_site.h, or OpenSSL.

### A3. Feature support (pjsua C API; header = pjsip/include/pjsua-lib/pjsua.h @2.17)
- **Multiple accounts**: yes (pjsua_acc_add etc.).
- **Transports**: UDP, TCP, TLS; IPv6 via `pjsua_ipv6_use` (DISABLED/ENABLED/ENABLED_PREFER_IPV4/PREFER_IPV6) per account/UA.
- **SSL backends** [V, SSL guide]: OpenSSL (default; also BoringSSL/LibreSSL), GnuTLS, Apple Secure Transport (deprecated), **Apple Network.framework (APPLE, macOS 10.15+/iOS 13+, needs ioqueue=select)**, **Windows Schannel (5)**, Mbed TLS (3.6/4.x). Autoconf never auto-selects Apple-Network or Schannel - set in config_site.h.
  - **OpenSSL-only features**: DTLS-SRTP (`PJMEDIA_SRTP_HAS_DTLS` force-disabled otherwise; default 0, set to 1), `on_verify_cb`, curves/sigalgs, cert_direct, SHA-256 digest auth, secure `pj_ssl_rand_bytes` (also Apple-Network, mbedTLS). OpenSSL/mbedTLS trust only app-supplied CAs; Apple/Schannel/GnuTLS use system store. GnuTLS: need >= 2.17 (verify bypass fix).
  - Recommendation: OpenSSL 3.x everywhere (uniform behaviour, DTLS-SRTP, SHA-256 auth); Schannel/Apple only if you want to shed OpenSSL.
- **SRTP**: SDES (`use_srtp` OPTIONAL/MANDATORY, `srtp_secure_signaling`) and DTLS-SRTP (OpenSSL). Bundled libsrtp in third_party/srtp.
- **ICE/STUN/TURN**: yes (account media_config / `pjsua_media_config`, `ice_cfg`, `turn_cfg` per acc). 2.17 fixed ICE UAF/race bugs.
- **BLF**: `pjsua_buddy_subscribe_dlg_event()`, `pjsua_buddy_get_dlg_event_info()`, callbacks `on_buddy_dlg_event_state`, `on_buddy_evsub_dlg_event_state`, `pjsua_buddy_config.subscribe_dlg_event`; RFC 4235 package **since 2.16**, `PJSUA_HAS_DLG_EVENT_PKG` default 1 [V pjsua.h L477]. Not in 2.15 and earlier.
- **MWI**: yes (`mwi_enabled`, `enable_unsolicited_mwi`, `on_mwi_info`). **Presence/SIMPLE**: yes (buddies). **SIP MESSAGE**: `pjsua_im_send`, `on_pager2`, typing indication.
- **REFER**: `pjsua_call_xfer` (blind), `pjsua_call_xfer_replaces` (attended), callbacks `on_call_transfer_request2`, `on_call_transfer_status`, Replaces handling `on_call_replace_request2`. Hold via `pjsua_call_set_hold` (RFC3264 default).
- **Call park/pickup**: no dedicated API; park = blind transfer to park orbit extension (REFER) [U feasibility but standard]; directed pickup = INVITE to feature code (*8/ **) or INVITE with `Replaces`/ Asterisk-specific; BLF dialog-info gives the target dialog id (use `pjsua_buddy_dlg_event_info`, then INVITE with Replaces for Asterisk-style pickup) [U].
- **Conference bridge**: yes (`pjsua_conf_*`, 2.16 adds parallel bridge). Three-way calls via connecting call slots.
- **WAV recording/playback**: `pjsua_recorder_create`, `pjsua_player_create`.
- **DTMF**: RFC 2833/4733 (default), SIP INFO, in-band via `pjsua_call_send_dtmf(param.method)`; receive via `on_dtmf_digit2`/`on_dtmf_event`.
- **Session timers** (`use_timer`), **100rel** (`require_100rel`): account config [V].
- **Codecs** [V pjmedia-codec/config.h and sources]: G.711 (built-in), L16, GSM (bundled), iLBC (bundled), Speex (bundled; `PJMEDIA_HAS_SPEEX_CODEC` 1), G.722 (built-in), G.722.1 (bundled g7221), **Opus** (`opus.c`; needs libopus, autodetected `--with-opus`, CMake FindOPUS), **G.729 via bcg729** (`bcg729.c`; `--with-bcg729`, GPLv3 lib OK for GPL app, patents), **AMR-NB/WB** via opencore-amr (`opencore_amr.c`), SILK (`silk.c`, needs external SDK), Lyra, passthrough/IPP (commercial). Video: openh264 (external, `--with-openh264`), VideoToolbox H.264 (Apple), libvpx VP8/VP9 (`vpx.c`), ffmpeg (`ffmpeg_vid_codecs.c`, GPL concerns), Android MediaCodec [U].
- **Echo cancellation**: Speex AEC (`PJMEDIA_HAS_SPEEX_AEC` 1, built-in), WebRTC AEC (legacy, `echo_webrtc.c`), **WebRTC AEC3 bundled** in `third_party/webrtc_aec3` (`--enable-libwebrtc-aec3`; `PJMEDIA_HAS_WEBRTC_AEC3` default 0; CMake: not on Apple/MinGW) [V]. Noise suppression: legacy WebRTC AEC module ships NS; speex preprocess in third_party/speex [U]. Alternative: use platform AEC (Android VOICE_COMMUNICATION source via Oboe, iOS VPIO via CoreAudio dev `PJMEDIA_COREAUDIO_...` voice processing) [U].
- **Video per platform** [V file list pjmedia-videodev]: Android `android_dev.c` (Camera/Camera2 via Java, needs JNI + Java classes) + `android_opengl.c`; iOS/macOS `darwin_dev.m` (AVFoundation capture) + `ios_opengl_dev.m`/`metal_dev.m` render; Windows `dshow_dev.c` (DirectShow capture, no MediaFoundation) + SDL/OpenGL render; also ffmpeg, v4l2, qt_dev, colorbar, avi. 
- **Flutter Texture rendering**: pjsua has no frame callback in the public C API for video windows by default. Options: (1) register a custom `pjmedia_vid_dev_factory` with `pjmedia_vid_register_factory()` (videodev.h [V]) implementing a render device whose `put_frame` copies I420/RGBA frames into a buffer you hand to Flutter (Android: SurfaceTexture/ANativeWindow; iOS/macOS: CVPixelBuffer via FlutterTexture `copyPixelBuffer`; Windows: `PixelBufferTexture`/GPU surface texture). (2) Use `pjmedia_vid_tee`/ port tap on the decoded `pjmedia_port` from `pjsua_call_get_info` (`pjsua_vid_conf` port) and call `pjmedia_port_get_frame`. (3) Flutter side: texture registrar API per platform. This is real engineering work (weeks) -> treat video as phase 2.
- **Misc**: RTT (RFC 4103) since 2.16; AI media port new in 2.17 (not needed).

### A4. SIP over WebSocket
- [V] **No SIP WS/WSS transport in pjsip** (no sip_transport_ws*.c in tree; transports = loop/tcp/tls/udp). GitHub issues #3239, #2512, #4348 closed with "no plan" (https://github.com/pjsip/pjproject/issues/3239). 2.17 added only an *experimental generic* WebSocket client in pjlib-util (`pj_websock`, PR #4859; client-only, blocking DNS) for AI streaming, not SIP.
- Options: implement an out-of-tree `pjsip_transport` (RFC 7118) on top of `pj_websock` (feasible, moderate effort, unmaintained upstream), or use a SIP proxy/SBC (Kamailio/Asterisk) offering UDP/TLS. Only needed if your server supports WSS only; most PBXes also offer TLS/UDP.

### A5. Gotchas
- **Threads**: every foreign thread (Dart isolate/UI thread, JNI thread) calling any pj_* / pjsua_* must first call `pj_thread_register(name, &desc_storage, &thread_handle)` once per thread; the `pj_thread_desc` must live for the thread's lifetime (static/thread_local); check `pj_thread_is_registered()` [V docs]. Best design: do **not** call pjsua from Dart threads at all; run pjsua on one dedicated native "engine" thread with a command queue (FFI calls only enqueue). Also: pjsua callbacks fire on pjsip worker/media threads - never call blocking pjsua APIs inside them; never call into Dart synchronously from them (see E). 2.17 notes much deadlock work; keep `thread_cnt`/`worker_thread` config default and avoid `pjsua_call_*` from within callbacks beyond lightweight ones.
- **Android audio routing**: Oboe/JNI backends don't pick speaker/earpiece/Bluetooth; use Android `AudioManager`/`AudioDeviceInfo` (Kotlin, via platform channel) to set mode `MODE_IN_COMMUNICATION`, `setCommunicationDevice` (API 31+), request audio focus; pjmedia Oboe input preset should be VoiceCommunication [U]. Foreground service (microphone type), `RECORD_AUDIO`, notification permission, Doze/FCM wake for incoming calls (SIP push needs a push gateway; pjsip doesn't do push itself).
- **iOS**: pjsip's coreaudio dev configures AVAudioSession itself; with CallKit you must let CallKit own activation: set `PJMEDIA_COREAUDIO_...` / don't open the sound device until `provider(_:didActivate:)`, i.e. call `pjsua_set_no_snd_dev()` (or `pjsua_set_null_snd_dev`) while call is pre-activation, then `pjsua_set_snd_dev(...)` after CallKit activates the session, and release on `didDeactivate` [U on exact flags; the callbacks/APIs are in pjsua.h L9000-9049 and L2102 comment about `pjsua_set_no_snd_dev`]. Background: VoIP push (PushKit) mandatory for incoming calls; app must report to CallKit immediately; SIP registration over TCP/TLS is killed in background, so re-register after wake. Apple Network.framework TLS backend avoids OpenSSL on iOS but needs ioqueue=select.
- **Network changes**: `pjsua_handle_ip_change(&param)` [V pjsua.h L3387]: restarts listeners, re-registers, updates contact/Via, and re-INVITEs or hangs up calls (`acc_config.ip_change_cfg`); progress via `on_ip_change_progress`. Call it from your connectivity-plus/NetworkCallback signal (debounced); on Android pass interface changes after the new network is validated. Needs `contact_rewrite`/`allow_via_rewrite` settings reviewed.
- Library init: `pjsua_create` -> `pjsua_init` -> transports -> `pjsua_start`; destroy on engine thread only. Set `log_cfg` callback to forward logs. On Android set `PJ_ANDROID` JNI context if JNI audio used.
- 2.17 behaviour change: INVITE transaction termination delay (#4765) - re-test interop with your PBXes.

## B. Alternatives
- **Linphone SDK (liblinphone C/C++ API)**: **AGPL-3.0** (GitHub: BelledonneCommunications/linphone-sdk, liblinphone) with paid commercial license; README: for client-side apps AGPL ~ GPLv3 terms; default build has "NO GPL third parties" flavour but still GPL/AGPL for Belledonne code [V README]. Feature-rich (ZRTP via bzrtp, WS/WSS support native [U], video, conferencing, push), actively released (v4.12.0 2026-09-30). Prebuilt: Android (Maven), iOS/macOS (CocoaPods / SPM), Windows/Desktop zip via download.linphone.org [V README mentions LinphoneSDK.windows, SPM, Maven-style bundles; fetch details to confirm]. C API is object/callback-heavy and large; binary size big (tens of MB); FFI surface is heavier than pjsua.  https://github.com/BelledonneCommunications/linphone-sdk
- **baresip / libre**: **BSD-3-Clause** (baresip/baresip, baresip/re; active, last push 2026-10). C, modular, light, SIP+ZRTP module, WebRTC-ish features (ICE, SRTP/DTLS), good opus/g711. No official prebuilt binaries for all 4 platforms; Android/iOS/Windows ports exist but are community-level; no first-class mobile audio/Windows story vs. pjsip; no BLF/dialog-event subscription [U]. Good only if you want permissive licence and are happy to do platform work. https://github.com/baresip/baresip
- **Flutter plugins** (from pub.dev search; not verified in depth): no single maintained plugin covers Android+iOS+Windows+macOS for PJSIP or Linphone. `pjsip_connect_flutter` (Android+iOS, prebuilt pjsip, early), `flutter_rust_sip` (PJSIP via Rust FFI; Linux focus), `flutter_nmsip` (Android, PJSIP, no recognised license), `linphone_flutter_plugin` (Android only), `flutter_pjsip`/`sip` (stale/early), `sip_ua` (pure-Dart SIP over WebSocket, JsSIP-like; works on all Flutter platforms but needs WSS-capable server and flutter_webrtc) [U for last one]. Conclusion: build own plugin; none worth depending on.

## C. IAX2
- [V via search] **iaxclient** (LGPL-2.1+ library from SourceForge, 2.1beta3, still packaged by Fedora/FreeBSD but upstream effectively dormant; docs date to 2007; only forks on GitHub, e.g. zlargon/iaxclient last push 2024, LGPL-2.1). It bundles portaudio + codecs + its own UI-less API; Windows/macOS/Linux; no mobile story. libiax2 (Asterisk/old) is abandoned [U]. A Rust crate `iax2` 0.2.0 exists, experimental (https://docs.rs/crate/iax2/0.2.0).
- Recommendation: **implement a minimal IAX2 client yourself** (in C within the engine lib, or in Dart over dart:io UDP) rather than adopt iaxclient. Minimal scope [U, from RFC 5456 knowledge]:
  - One UDP socket (port 4569), full frames (F bit, source/dest call number, timestamp, oseq/iseq, frame type, subclass), mini voice frames (no F bit, 16-bit timestamp), ACK/retransmit logic with sequence numbers, PING/PONG/LAGRQ, call-number multiplexing, timestamp wrap handling (mini frame's 16-bit TS + periodic full-frame voice).
  - Registration: REGREQ -> REGAUTH (MD5 challenge: MD5(challenge+secret) hex, or RSA) -> REGREQ w/ MD5 result -> REGACK; refresh timer.
  - Calls: NEW (with codec bitmask, called/calling number, username) -> AUTHREQ (MD5) -> AUTHREP -> ACCEPT (codec chosen) -> RINGING -> ANSWER; HANGUP/REJECT; DTMF via IAX control frames; HOLD/UNHOLD; TRANSFER optional.
  - Media: ulaw/alaw trivial (g711 encode/decode tables - reuse pjmedia g711 or write 50 lines); GSM via pjmedia's bundled gsm lib; jitter buffer needed (pjmedia jbuf reusable).
  - Effort estimate: roughly 1.5-3 kLOC and 2-4 developer-weeks for REG+calls+ulaw/alaw with interop tests against Asterisk; the hard parts are retransmission/timestamp edge cases and NAT. Integrating with pjmedia (as a custom media port feeding the conference bridge) avoids writing audio IO again. Also consider whether IAX2 is truly needed: Asterisk deprecates chan_iax2 usage in new deployments and many PBXes (FreePBX) still support it but usage is shrinking.

## D. ZRTP
- **GNU ZRTP C++ (wernerd/ZRTPCPP)**: RFC 6189; README says core ZRTP sources relicensed from LGPL to **Apache-2.0** (some crypto files, e.g. Brian Gladman AES/SHA2, have their own licences) [V README + LICENSES/summary.md]; GitHub shows "NOASSERTION". Active (push 2026-06). Commonly packaged as GPL-3.0+ in older distro packages (libzrtpcpp 2.x) - check version.
- **ZRTP4PJ (wernerd/ZRTP4PJ)**: glue implementing a `transport_zrtp` + a replacement SRTP for **pjproject 1.x**; tested "1.8.5, 1.10, trunk", last push 2024-06 (no real maintenance); no license file detected via GitHub API [V]; needs pjsua patch/callbacks (since merged long ago) and OpenSSL. **Integration with 2.17 is unverified and will likely need porting** (pjmedia_transport API, SRTP API, build system). Effort: medium-high.
- **bzrtp (Belledonne)**: **GPL-3.0** (dual commercial), actively maintained (push 2026-10-12), C library, transport-agnostic (you feed RTP/ZRTP packets and get keys), used by Linphone [V]. For pjsip you would write a `pjmedia_transport` adapter that intercepts ZRTP packets on the RTP socket and then configures SRTP keys on pjmedia's SRTP transport (`pjmedia_transport_srtp_start`) - similar in shape to ZRTP4PJ. GPLv3 is fine for a GPL app. Feasibility: medium (~2-3 weeks); no off-the-shelf pjsip-2.17 integration known [U].
- Practical advice: ship SDES/DTLS-SRTP first; ZRTP as later opt-in (also needs interop with Asterisk? Asterisk does not support ZRTP natively [U]; ZRTP only peer-to-peer between softphones).

## E. Dart FFI integration
- **Event delivery from native threads**:
  - `NativeCallable.listener` (Dart >= 3.1) [V api.dart.dev]: callable from **any thread**, posts to the owning isolate's event loop asynchronously (void return only [U]), no blocking; must `close()`, and `keepIsolateAlive` controls isolate liveness. Easiest to use; pass the `nativeFunction` pointer to your C lib at init.
  - `Dart_PostCObject_DL` via `dart_api_dl.h` + `Dart_InitializeApiDL(NativeApi.initializeApiDLData)`; native side posts `Dart_CObject` (ints/strings/typed data/external typed data) to a `ReceivePort.sendPort.nativePort`. Works from any thread, no function-pointer-per-callback mapping, lets you send structured/binary payloads (e.g. serialized event structs, video frame notifications) with zero Dart callable plumbing, and is the pattern used by official sqlite/`package:ffi` examples; need to bundle dart_api_dl.c in your lib.
  - Recommendation for Flutter 3.32/Dart 3.8: **Dart_PostCObject_DL with a single event queue** (engine thread serializes events -> posts one message type; Dart side decodes). It is robust, has no per-callback overhead, handles shutdown cleanly (just stop posting), and avoids the "callable closed while a native thread still calls it" crash class. `NativeCallable.listener` is fine for prototyping/low-volume use. Do not use `isolateLocal` (same-thread only). Never call Dart synchronously from pjsip threads. Keep calls into native non-blocking (enqueue commands; long ops return via event).
- **Bundling native libs** [general knowledge; U on exact current plugin templates]:
  - Android: `android/src/main/jniLibs/<abi>/libsoftphone.so` (+ libssl/libcrypto/liboboe/libc++_shared); load with `DynamicLibrary.open('libsoftphone.so')`. Or build via Gradle `externalNativeBuild` CMake in the plugin; 16 KB alignment flags needed.
  - iOS: ship `Softphone.xcframework` (static pjsip + your glue) in plugin podspec `vendored_frameworks`; use `DynamicLibrary.process()` (static link) and lookups by symbol; guard against dead-strip: add `-force_load`/`-Wl,-all_load` or reference symbols from a Swift/ObjC file, and set `STRIP_STYLE = non-global` / `DEPLOYMENT_POSTPROCESSING=NO` so `dlsym` finds exported C functions (Xcode release strips unexported symbols). Mark exports `__attribute__((visibility("default"), used))`.
  - macOS: dylib/framework in `<App>.app/Contents/Frameworks` via podspec `vendored_libraries`/`vendored_frameworks`, codesign + notarize; `DynamicLibrary.open('libsoftphone.dylib')` with @rpath. Universal binary required for both arches.
  - Windows: DLL (and OpenSSL DLLs, VC runtime) next to the exe via plugin `CMakeLists.txt` `<plugin>_bundled_libraries`; `DynamicLibrary.open('softphone.dll')`.
  - Federated plugin vs. one FFI plugin (`flutter create --template=plugin_ffi`) with per-platform native build is the supported structure.
- **Native assets / hooks**: Build hooks (`hooks` + `code_assets` packages, `hook/build.dart`) became stable around Flutter 3.38 / Dart 3.10 (Nov 2025; code_assets 1.0.0 stable per pub.dev score page; https://dart.dev/tools/hooks) [V via search, partially]. **Not available in Flutter 3.32/Dart 3.8** (was experimental flag then) - if you stay on 3.32, use the classic FFI plugin template. If you can upgrade to >=3.38, hooks can compile C glue (via native_toolchain_c) and bundle prebuilt libs per target, replacing manual jniLibs/podspec plumbing; but building pjsip itself in a hook is impractical - ship prebuilt per-platform artifacts (CI-built, downloaded by the hook).

## Key decisions / risks (summary)
1. Use pjproject 2.17; GPLv2-or-later, so release the app GPLv3 (or v2+). App Store distribution of GPL is a policy risk.
2. Own C glue library with dedicated engine thread + command queue + `Dart_PostCObject_DL`; do not call pjsua from Dart threads.
3. OpenSSL 3.x on all platforms (DTLS-SRTP, SHA-256 auth); Opus + G.722 + G.711; AEC3 via `--enable-libwebrtc-aec3` (not available in CMake on Apple) or platform AEC.
4. Build matrix: Android configure-android + Oboe + 16KB pages; iOS configure-iphone x3 (device/sim arm64, sim x86_64) -> xcframework; macOS two-arch lipo; Windows MSBuild vs14.sln (CI only tests Win32; x64 works in .sln but verify; ARM64 unclear). CMake in pjproject is experimental (Linux/macOS only).
5. BLF needs >=2.16 (`pjsua_buddy_subscribe_dlg_event`); call park/pickup done with REFER/feature codes.
6. No SIP over WebSocket in pjsip; no mature Flutter plugin spans 4 platforms.
7. Video to Flutter Texture needs a custom vid_dev factory; Android camera needs JNI/Java; defer to phase 2.
8. IAX2: write own minimal client (2-4 weeks); iaxclient is dormant LGPL.
9. ZRTP: bzrtp (GPLv3) or GNU ZRTP C++ (Apache core) with a custom pjmedia_transport; ZRTP4PJ is for pjsip 1.x, stale. Defer.
10. Mobile call plumbing (PushKit+CallKit, FCM+ConnectionService, audio session handoff via `pjsua_set_no_snd_dev`/`set_snd_dev`) is the biggest hidden effort and is not provided by pjsip.
