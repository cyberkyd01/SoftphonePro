# Final principal review - 2026-10-19

Release-blocking review of SoftphonePro (C engine `native/`, PJSIP 2.17, and the app). This file tracks every finding
and its status. Native (engine) findings were fixed in the same pass; the app agent marks the app findings.

Status values: Fixed, Open, Pending (owner has not updated the row), Optional.

| ID | Severity | Area | Finding | Status | Fix / tests |
|----|----------|------|---------|--------|-------------|
| C1 | Critical | native | Remote unauthenticated DoS: `id_index_cmp` (`spc_call.c`) never advances on non-digit History-Info `index=` values (`a`, `1.a`, `-`, ...) and spins the pjsua worker thread forever (reached from `emit_incoming` -> `id_store` -> `id_parse`). | Fixed | The index is sanitised to `[0-9.]+` (otherwise treated as no index) and `id_index_cmp` is progress-safe (no progress and not at `.` -> `strcmp` fallback; iteration guard). All other parse loops audited (identity parser, `spc_presence.c` dialog-info XML and MWI, `spc_iax2_proto.c` IE loop, `spc_ws_transport.c` frame and upgrade parsing, `has_token`): each advances on every iteration. Tests: `test_caller_identity.Ident.test_raw_history_info_malformed_index_no_hang`, `test_raw_history_info_valid_order_survives_sanitising`, `test_raw_identity_fuzz_liveness` (300 INVITEs, fixed seed). Each asserts `core.ping` within 2 s and a canary INVITE still reaching `call.incoming` (ping alone is served by the request worker and cannot see a wedged pjsua thread). The malformed-index test was confirmed to fail on the pre-fix code. |
| C2 | Critical | app / Android | Exported `MainActivity` reachable by explicit intents: raw `intent.data` forwarded; `softphonepro-cli://` trusted as local CLI (dial without consent, provisioning with automation); `ACTION_ANSWER` with a guessable `callKey`; automation API started on every platform. | Fixed | `MainActivity.kt` forwards only `tel/sip/sips/callto/softphonepro`; ANSWER / OPEN_ROUTE / show-over-lockscreen require a persistent random nonce (`Prefs.intentNonce`, constant-time compare) that only our own immutable explicit PendingIntents carry (`NotificationHelper`, `bringToFront`); decline/hangup already go through the non-exported `CallActionReceiver`. Android and iOS Dart sides use `parseLink` (allowlist). `classifyLink(..., isLocal)` refuses `softphonepro-cli` unless the link was built from this process's own launch args (identity-based `isLocalLaunchLink`); unknown schemes rejected. `AutomationService` gated to macOS/Windows/Linux (`automationSupportedProvider`). `BootReceiver` now `exported=false` and checks the action. Release manifest verified with `aapt dump xmltree`: no DebugReceiver; exported = MainActivity, `SpConnectionService` (BIND_TELECOM_CONNECTION_SERVICE), `ProfileInstallReceiver` (DUMP). Emulator: CLI dial link, ANSWER `--es callKey 1` and OPEN_ROUTE without nonce are logged and ignored; `tel:600` fills the dialer, no call placed. Tests (`app/test/security_review_test.dart`): 'softphonepro-cli from the OS is rejected on every platform', 'allowed schemes pass, others are refused', 'Android link events go through the allowlist parser', 'an OS-delivered softphonepro-cli dial link places no call', '... provision link imports nothing', 'a real --dial launch argument still dials', 'does not start on TargetPlatform.android/iOS even when enabled', 'platform predicate'. |
| M1 | Major | native | Hostile WAV hangs `wav_open` on Windows / 32-bit: uint32 chunk sizes cast to `long` for `fseek(SEEK_CUR)` go negative (LLP64) and seek backwards forever (`media.fileInfo`, `call.playFile`, `call.hold{music}`). | Fixed | 64-bit offsets (`_fseeki64` / `fseeko`), file size tracked, chunks extending past EOF end the walk, 1000-chunk cap, odd-size padding handled, `fmt` size checked against the file, `data` size clamped to the real file. Tests: `test_media_files.TestHostileWav` (`test_huge_and_negative_chunk_sizes`, `test_data_chunk_sizes_lie`, `test_odd_sizes_and_padding`, `test_fmt_after_data_and_missing`, `test_truncated_headers`, `test_zero_length_data_and_zero_size_chunks`, `test_many_tiny_chunks`, `test_hostile_wav_in_call_paths`): each returns in under 1 s and leaves the engine responsive. The platform-specific hang itself cannot be reproduced on macOS/LP64; the tests cover the logic that prevented it. |
| M2 | Major | app | Provisioning export dumped `settings.toJson()` (automation token, app lock, instanceMac, update state, onboardingDone). | Fixed | `Provisioning.exportableSettings` allowlist (`exportSettings`). Tests: 'never contains automation, app lock, instance id or update state', 'every exported key is a real user-facing setting' (`app/test/security_review_test.dart`). |
| M3 | Major | app | Provisioning imports could change dangerous settings: web-link consent did not reveal them, and the Settings-screen import (QR, URL, pasted JSON, file) applied everything without any check. | Fixed | One trust model: TRUSTED = local CLI `--provision` only (`applyTrustedImport`, automation still applies); UNTRUSTED = web link, QR, pasted URL/JSON, file, Settings URL fetch. All untrusted imports go through `prepareUntrustedImport` (`services/provisioning_import.dart`) and one dialog (`showImportConfirmDialog`, `ui/widgets/import_confirm_dialog.dart`), used by `link_handler.dart` and `provisioning_section.dart`; `importProvisioningResult` defaults to the untrusted path. `kSettingImportPolicy` classifies every AppSettings key (allowed / flagged / forbidden / refused). Refused (whole import aborted): `tlsVerify:false`, `customCaFile`, `tlsPins`, `dnsServers`, `automation*`, `appLock*`. Forbidden keys (all path settings, device names, ports/transports/STUN, LAN sharing, hotkeys, startAtLogin, globalStatus, useSimulator, update*, instanceMac, onboardingDone, unknown keys) are dropped and listed as ignored. Flagged: auto-answer and auto-record (off unless ticked), forwarding target, intercom, dial rewriting, feature codes, links-immediately, logging/SIP trace, blocklist, emergency numbers, speed dial, recording auto-delete. Accounts: server / registrar / proxies / transport / TURN / headers / caller id shown, `tlsClientCert` dropped, audio refs validated. Tests: `test/provisioning_trust_test.dart` (every bypass through web link, QR, pasted JSON, file and Settings URL fetch; allowlisted keys apply; flags shown; CLI still applies automation; key-classification test fails when an AppSettings key is unclassified), plus the M3 tests in `test/security_review_test.dart`. |
| M3a | Major | app | Review of the first M3 fix: `tlsPins` from a web link accepted (pinning an attacker certificate bypasses TLS verification, host is advisory). | Fixed | `tlsPins` is refused for every untrusted import. Test: 'a refused setting imports nothing' in each channel group. |
| M3b | Major | app | `dnsServers` accepted from untrusted imports (attacker resolvers redirect all SIP traffic). | Fixed | `dnsServers` refused; also removed from `Provisioning.exportableSettings` together with `tlsVerify` and `tlsPins`. |
| M3c | Major | app | Path settings unflagged: `recordingFolder` (UNC path exfiltrates recordings), `lanDownloadsDir` + `lanAutoAcceptFiles` + `lanEnabled`, `customCaFile`, announcement / notice files, audio device names; auto-record (`autoRecord`, `recordRule`, per-account `always`) unflagged. | Fixed | Path and device keys forbidden (dropped and listed); `customCaFile` refused; auto-record is flagged and off unless its checkbox is ticked. Tests: 'allowlisted keys apply, the rest is listed as ignored', 'dangerous settings are dropped and listed ...'. |
| M3d | Major | app | Settings-screen import (QR, pasted URL/JSON, file) applied `{...r.settings}` directly: automation*, appLock*, tlsVerify:false, customCaFile, tlsPins, instanceMac, update* all applied after a counts-only dialog. | Fixed | `applyProvisioning` now uses `prepareUntrustedImport` + `showImportConfirmDialog` + `applyImportPlan`. The Settings URL fetch also honours the injectable HTTP client. Tests: channel groups in `provisioning_trust_test.dart`. |
| M3e | Minor | app | Lower-severity settings unflagged: `speedDial`, `emergencyNumbers`, `blocklist`, `useSimulator`, `hotkeys`, `startAtLogin`, `globalStatus`. | Fixed | speedDial / emergencyNumbers / blocklist flagged; the others forbidden. |
| M3f | Minor | app | macOS Apple-event URL payloads were parsed with `parseForwardedArgs`, so a payload with embedded newlines could be read as `--provision`. | Fixed | `DesktopChannel._handlePayload` routes macOS payloads through `parseLink` only. Windows keeps argv forwarding (same-user privilege, documented in code). Tests: 'macOS Apple-event payloads are links, never command-line flags'. |
| M3g | Minor | app | `redactSecrets` missed `a=ice-pwd:` and JSON-form secrets. | Fixed | Both masked (also escaped-quote form). Tests: 'redactSecrets: ICE passwords and JSON secrets'. |
| M3h | Minor | app | `classifyLink` reported unsupported schemes as `notLocal` (wrong message). | Fixed | New `LinkRejection.unsupportedScheme` with its own ARB string (all 14 ARB files). Test: 'unsupported scheme is distinct from notLocal'. |
| M3i | Minor | app | LAN confirm dialog put the peer name and host into one string. | Fixed | Peer name shown as plain text (control and bidi characters removed, capped at 40), `Address: host:port` on a separate line. Test: 'markup and control characters are inert ...'. |
| M4 | Major | app | Diagnostic bundle appended the raw engine.log tail. | Fixed | `redactedEngineLogTail` (applies `redactSecrets`) used by the bundle. Test: 'digest Authorization and a=crypto lines are masked'. |
| M5 | Major | docs | Release notes, changelog and features contradicted what ships: localisation, encryption, update checker, media keys, automation-API platforms and counts. | Fixed | RELEASE_NOTES_v1.0.0.md, CHANGELOG.md (Unreleased folded into 1.0.0, new Security section), README.md and FEATURES.md counts all agree; the automation API is now desktop-only in code (C2). |
| m1 | Minor | native | `spc_denoise_start` never reset `g_mic_slot` / `g_mic_dn`, shutdown left `g_en[]` set: stale slot across `core.stop`/`core.start`. | Fixed | Start resets the mic slot; shutdown clears `g_en[]`; a `g_stopping` flag (set at shutdown, cleared at start, checked under the publish lock) prevents any processor being created between shutdown and `pjsua_destroy`. Test: `test_voice_isolation.TestVoiceIsolationCalls.test_stop_start_cycles_with_isolation` (20 stop/start cycles with isolation on, a call after each). |
| m2 | Minor | app | `softphonepro://lan` connected without a prompt. | Fixed | "Connect to device X?" dialog before `connectManual`. Test: 'softphonepro://lan shows a confirm dialog; cancel does not connect'. |
| m3 | Minor | app | Plaintext `.bak-*` left after enabling encryption. | Fixed | Backups are overwritten and deleted right after the verified post-migration reopen (`shredFile`); footer text updated in all 14 ARBs. Test: `test/storage/encrypted_db_test.dart` 'migrates plain -> encrypted -> plain keeping all records' (backup list empty immediately). |
| m4 | Minor | app | LAN intercom auto-allowed by default. | Fixed | `lanIntercomPrompt` defaults to true (explicit stored false kept); pairing dialog says intercom requests are asked first. Test: 'default is true; an explicit false is kept'. |
| m6 | Minor | app | Remaining English strings. | Fixed | `callErrHandoffFailed`, `callErrCouldNotSendToDevice`, `callForegroundServiceText` were already localised in all ARB files and used via l10n; verified. |
| m7 | Minor | docs | App lock scope undocumented. | Fixed | Sentence added to `docs/USER_GUIDE.md`. |
| m5 | Minor (perf) | native | MP3 files up to 200 MB were read fully into memory; `call.hold{music}` on big files. | Fixed | MP3 input file cap lowered to 64 MB (`SPC_PLAY_MAX_MP3_BYTES`, `ENGINE_API.md` updated). Duration for `media.fileInfo` is already header-based (minimp3 `MP3D_SEEK_TO_BYTE`: no full decode); decoding runs on a helper thread per play, so neither `call.hold{music}` nor `call.playFile` waits for it. Only the up-to-64 MB file read happens on the worker. |
| m8 | Minor | native | `spc_rec.c` `rec_thread` used unchecked `malloc` for its transfer buffers. | Fixed | Buffers are now fixed-size stack arrays (24 KB); no allocation can fail in the writer thread. Covered by the existing recording tests in `test_media_files.TestRecording`. |
